Doom inside Doom inside Doom inside the first Doom

Doomception

Three Doom games in one DOOM2.EXE. Each one shows the next on a wall.

Why it's cool

Four reasons

  1. No operating system. DOS has no processes or threads. It's all done by hand, inside the game.
  2. The nesting is visible. Each game's wall shows the next game, and the picture loops.
  3. A few instructions to pause one game and resume another.
  4. A program written to run alone is made to share. Only what differs is swapped: about 1,300 bytes per switch out of 577 KB.

The model

How it works

  • One DOOM2.EXE: its code and data are shared by every copy.
  • Each copy, a depth, has its own memory: heap, stack, screen buffer, ACE code.
  • One CPU runs one depth at a time.
  • Every 4 frames a switch swaps in the next depth's data, patches and pointers, then hands it the CPU.
  • Each depth draws the next one on a wall.

ACE: a Doom 2 mod, shipped as a WAD, that adds engine code. The switch is part of it.
