Doom inside Doom inside Doom inside the first Doom

Doomception

Three copies of Doom running inside one DOOM2.EXE under DOS, with no operating system to help, each one showing the next on a wall.

Why it's cool

Four things worth the trip

  1. Three games in one program, with no operating system. DOS has no processes, no threads, no memory protection. Everything an operating system would do for you is done by hand, inside the game.
  2. The nesting is literally visible. Each game's walls show the next game's live picture, and the deepest one shows the first, so the picture loops.
  3. Pausing a running game and resuming another takes a handful of instructions. Save a few registers, swap one stack pointer, and a different game carries on where it stopped.
  4. A program written to be alone is made to share. All three games use the same code and the same data addresses. They are kept apart by swapping only what differs: about 1,300 bytes per switch out of 577 KB, plus 406 code patches and a few pointers.

The model

How it works, in one paragraph

DOOM2.EXE is loaded once: its code and data sit at fixed addresses, and every copy of the game uses those same addresses. Each copy, a depth, also gets private memory of its own: a heap, a stack, a screen buffer and its own copy of ACE's code. The CPU runs one depth at a time. Every 4 frames, a switch runs: host code whose own state lives outside every depth. It saves the running depth's copy of Doom's writable data and of the code patches its ACE made, loads the next depth's, points Doom's shared heap and screen pointers at that depth's private memory, and swaps the CPU's stack pointer, so the next depth resumes exactly where it stopped. Each depth draws the next depth's latest frame onto a wall, and the deepest draws the first.

ACE is a mod for DOS Doom 2 that comes as a WAD file. It adds its own engine code to the game, and the code that runs the copies is part of it.
