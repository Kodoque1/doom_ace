Animation re-enactments written for this page, from the code in nested/ and doom_ace/engine/. Lines marked measured come from the project's logs, README, HANDOFF and commits. No game data is used.

How the page is built, following that research: you set the pace, each key step asks for a prediction first, every depth keeps one colour, and each scene starts from the previous one's picture. ← and → step the scene on screen.

Further reading: Hundhausen, Douglas & Stasko, A Meta-Study of Algorithm Visualization Effectiveness (JVLC 2002) · Tversky, Morrison & Bétrancourt, Animation: Can It Facilitate? (IJHCS 2002) · Guo, Online Python Tutor (SIGCSE 2013) · Lerner, Projection Boxes (CHI 2020) · Kang & Guo, Omnicode (UIST 2017) · Crichton, Gray & Krishnamurthi, A Grounded Conceptual Model for Ownership Types in Rust (OOPSLA 2023) · Victor, Explorable Explanations (essay, 2011).

The 3D scenes borrow from process and factory visualization: token replay of a logged schedule (van der Aalst, Adriansyah & van Dongen, WIREs DMKD 2012), flow bands for what moves (Xu et al., ViDX, TVCG 2017), and a marked simulation mode for what-if states, as digital twins do.
